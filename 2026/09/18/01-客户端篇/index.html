main.cpp

1. QSS

QSS = Qt Style Sheets，Qt 样式表文件，后缀一般是 .qss，本质上就是纯文本文件，语法思路和网页的 CSS 非常像，但专门用来美化 Qt 控件。（修饰 Qt 的窗口、按钮、输入框、表格等控件）

说明：

  • argc、argv 不需要你手动写代码传，操作系统在启动程序的时候自动准备好，自动传给 main 函数。
  • 全局生效：程序后面创建的所有窗口、控件（MainWindow、QDialog、QPushButton、QLabel 等），默认都会继承这套 QSS 样式。
  • 生效顺序规则：控件自身 setStyleSheet > 父窗口 setStyleSheet > 全局 QApplication setStyleSheet
  • a.setStyleSheet(style);,把 qss 文本交给 Qt 全局样式引擎。

2. ini文件读写

说明：

  • QSettings settings(config_path, QSettings::IniFormat);,创建一个 QSettings 对象，用来读写指定路径下的 ini 配置文件。
  • QSettings::IniFormat：告诉 QSettings，使用INI文件格式解析。
  • 读取语法：settings.value("节名/键名")

3. MainWindow w; 和 QApplication a; 的关系

a 是整个 Qt 应用程序的全局管理者；w 只是这个程序里的一个窗口对象。

说明：

  • a：唯一的应用实例，管理整个程序的事件循环、全局样式、剪贴板、窗口系统等。一个 GUI 程序只能有一个 QApplication。
  • w：MainWindow 类的局部对象，属于 a 管理下的一个顶级窗口。
  • w 依赖 a，必须先创建 a，再创建 w。如果顺序反过来，直接崩溃。
  • return a.exec();,启动 Qt 的事件循环（消息循环）,调用 exec() 之后，代码在这里阻塞，不再继续往下执行，进入无限循环，不断监听、分发界面事件。

mainwindow.cpp

整体思路：用一个 QMainWindow 主窗口作为容器，切换中心部件 (CentralWidget) 来实现【登录页 / 注册页 / 重置密码页】页面切换，没有弹出多个独立弹窗，全部在 MainWindow 内部切换。
三个页面：LoginDialog登录、RegisterDialog注册、ResetDialog重置密码，都继承 QDialog，无边框。

1. 设置LoginDialog为MainWindow的中心部件

说明：

  • Qt::FramelessWindowHint,去掉系统窗口边框 + 标题栏。
  • Qt::CustomizeWindowHint,自定义窗口提示标记,由程序完全自定义窗口外观，不使用系统默认窗口装饰,一般和 FramelessWindowHint 一起搭配使用；如果只写 FramelessWindowHint，部分平台 / Qt 版本可能还有残留窗口阴影、系统样式干扰，加上这个更干净。

logindialog.cpp

完整业务链：

  1. 用户点击登录按钮 → on_login_btn_clicked执行
  2. 校验邮箱、密码合法性，表单有错直接终止
  3. 无错误：禁用登录 / 注册按钮，避免重复点击
  4. 读取输入框内容，构造 json，密码异或加密
  5. 交给 HttpMgr 发送 HTTP 登录请求
  6. 等待服务端应答；应答回来后 HttpMgr 发射sig_login_mod_finish
  7. LoginDialog 的slot_login_mod_finish收到信号，取出_handlers里注册好的 lambda（initHttpHandlers里的登录回调）处理登录结果
  8. 登录失败：回调里showTip提示错误，enableBtn(true)恢复按钮；登录成功发射信号建立 TCP 长连接

1.LoginDialog::slot_login_mod_finish(ReqId id, QString res, ErrorCodes err)槽函数

HttpMgr 负责发送 HTTP 网络请求；当 HTTP 请求完成（成功 / 失败），HttpMgr 会发射 sig_login_mod_finish 信号，把 3 个参数抛出来

  1. 判断网络层面是否出错【ErrorCodes err：网络层面错误码（成功 / 超时 / 网络错误）】
  2. 将返回字符串解析为 QJsonDocument【QString res：后端返回的 json 字符串】
  3. 根据 ReqId，去_handlersmap 查找注册好的 lambda 回调，执行业务逻辑（登录成功后的处理）【ReqId id：请求ID，用来区分是哪一次http请求（登录、注册、找回密码等）】
  • jsonDoc.isObject(),如果原始 json 是{ ... }这种JSON 对象，isObject() 返回 true;如果是[ ... ]数组，或者不是合法对象，返回false
  • jsonDoc是QJsonDocument，jsonDoc.object()就是从 QJsonDocument 中取出根节点的 QJsonObject（也就是{ ... }大括号包裹的键值对对象）。
  • QMap<ReqId, std::function<void(const QJsonObject&)>> _handlers;,_handlers 是一个map 容器，用来存放不同网络请求对应的业务回调函数。

2. LoginDialog::initHead

initHead 是登录界面头像初始化函数，核心作用：加载资源里的头像图片，处理成圆角头像，在 QLabel 上展示。

3. 类的前向声明

说明：

  • 这叫类的前向声明（forward declaration），放在 logindialog.h 头文件里。告诉编译器：在 Ui 命名空间里面，存在一个名叫 LoginDialog 的类，但暂时不展示这个类完整内部代码。目的是让你可以在 logindialog.h 里写 Ui::LoginDialog *ui; 这个指针成员。
  • #include "ui_logindialog.h"实际写在了logindialog.cpp
  • 能够减少头文件依赖：如果直接在logindialog.h写#include "ui_logindialog.h"，只要 ui 界面一改，logindialog.h就会被认为改动，所有包含logindialog.h的文件全部重新编译，编译很慢。用前向声明，头文件不用包含自动生成的 ui 头，改动 ui 不会大面积触发重编译。
  • 这样的前向声明，只能在头文件里用来声明
  • Ui::LoginDialog和logindialog互相独立，Ui::LoginDialog是由界面文件logindialog.ui自动生成的

4. LoginDialog::initHttpHandlers

初始化 HTTP 回调映射表：注册【登录请求 ID】对应的回调 lambda。当登录 HTTP 请求收到后端 JSON 回包，就执行这个 lambda，解析登录返回数据；登录成功则组装服务器信息，发射信号去建立 TCP 长连接。

说明：

  • Uid：用户ID，唯一标识一个用户，由服务端分配，每个用户一个固定数字 ID
  1. TCP 长连接登录时，告诉服务端 “我是谁”
  2. 收发消息时，用来区分消息发送人、接收人
  3. 本地缓存，后续页面展示个人信息、查询聊天记录

  • Host：服务器主机地址，客户端 TCP 套接字要连到这个地址，找到聊天服务器。

  • Port：端口号，Host+Port 合在一起，才能定位到聊天服务

  • Token：身份令牌，登录凭证，相当于临时的 “通行证”；HTTP 登录成功后，后端生成的一串加密字符串；TCP 长连接握手的时候，发给服务端做身份校验

  • Host+Port：找到聊天服务器在哪（TCP 连接的目标地址）

  • Uid+Token：证明你是谁、登录身份合法（长连接鉴权）

5. LoginDialog::enableBtn

统一启用 / 禁用登录按钮、注册按钮

6. LoginDialog::AddTipErr

新增一条表单错误，存入错误 map 并在界面弹出红色提示；

说明：

  • _tip_errs[te] = xxx：如果 key 不存在就插入 key；key 存在则修改 value，键一定存在

7. LoginDialog::DelTipErr

移除指定类型错误；如果所有错误都删完，清空提示；还有错误则继续展示第一条错误。

说明：

  • remove(te)：删掉整条键值对，键消失
  • _tip_errs.first() 返回的是key 最小的那一条，不是第一次插入，也不是最后插入。
  • QMap 是升序有序容器，不是按插入先后排序！

8. 普通enum vs 强类型枚举enum class

说明：

  • 普通enum TipErr,枚举常量直接暴露在当前命名空间,例如AddTipErr(TIP_EMAIL_ERR, "邮箱错误");
  • enum class TipErr（强类型枚举）,枚举成员被封装在TipErr作用域里面，必须加TipErr::,例如AddTipErr(TipErr::TIP_EMAIL_ERR, "邮箱错误");
  • enum class可隐式转 int;enum class不能隐式转为 int

9. Qt 的自动关联槽函数命名规则

命名满足固定格式：on_ + 控件 objectName + _ + 信号名
当你编译项目，uic 工具（处理 ui 文件的工具）会自动生成代码，自动完成 connect 信号槽绑定，不需要手动写 connect ()。

说明：

  • 自动生成的代码，效果等同于手动写这句：connect(ui->login_btn, &QPushButton::clicked, this, &LoginDialog::on_login_btn_clicked);

registerdialog.cpp

业务流程：

  1. 打开注册窗口 → 构造函数执行，绑定信号、初始化定时器、注册 HTTP 回调；
  2. 用户输入表单，输入框失去焦点自动校验，实时维护_tip_errs错误集合；
  3. 输入邮箱，点【获取验证码】：
    • 正则校验邮箱；合法发送 HTTP 请求拿验证码；
    • 后端返回成功 → 启动 60s 倒计时，按钮置灰；
  4. 用户填写验证码、密码、确认密码；
  5. 点击【确认注册】：做表单判空校验，组装 JSON，发送注册 HTTP 请求；
  6. HTTP 返回成功 → ChangeTipPage()切换到注册成功页面，开启 5s 倒计时；
  7. 5 秒倒计时结束，自动发射sigSwitchLogin()，切回登录窗口；
  8. 随时点返回 / 取消，停止定时器，立刻切回登录。

说明：

  • 输入框失去焦点自动校验（重点！实时表单校验）
  • editingFinished：输入框失去焦点（用户点别的地方）触发。
  • 用户输完用户名，点到别的输入框，立刻自动校验用户名，有错就展示红色提示。
  • 邮箱、密码、确认密码、验证码输入框全部做了同样绑定。

clickedlabel.cpp

httpmgr.cpp

HttpMgr 是全局单例 HTTP 网络管理类，封装 Qt 的QNetworkAccessManager，专门统一发送异步 POST Json 请求，用信号槽把 HTTP 返回结果分发到对应的业务对话框（登录、注册、重置密码）。

核心设计思想：网络层 和 UI 业务层解耦

  • HttpMgr 只管发 http、收网络响应，不写任何登录 / 注册业务逻辑
  • LoginDialog / RegisterDialog 只需要监听对应模块的信号，处理返回的 json 数据

POST JSON 请求：使用 HTTP 的 POST 请求方法，请求体 (body) 里面放 JSON 字符串，同时在请求头告诉服务器：Content-Type: application/json。

application/json 是写在 HTTP 请求头 Content-Type 的值，专门搭配 POST（绝大多数场景） + 请求 Body 里面存放 JSON 字符串一起使用。作用是告诉服务端：本次 HTTP 的消息体（body）的数据是 JSON 格式，请用 JSON 解析器来解析 body。

HTTP 常见方法：

  • GET：参数一般放在URL 地址栏，没有请求 body，适合获取数据
  • POST：数据放在请求体（body），适合提交数据（登录账号、注册信息）

完整流程示例：

  1. LoginDialog 构造 QJsonObject，填入 email、passwd
  2. 调用HttpMgr->PostHttpReq
  3. HttpMgr：QJsonObject → 转 JSON 字节，设置Content-Type:application/json
  4. QNetworkAccessManager 发起 POST，把 JSON 塞进请求体发给服务端
  5. 后端收到 JSON，解析里面的邮箱密码，校验，返回 json 响应
  6. HttpMgr 收到后端返回，通过信号槽把返回字符串抛给 Dialog 处理

HttpMgr::GetInstance().get()

  • HttpMgr::GetInstance()得到的是shared_ptr，.get()：取出 shared_ptr 内部保存的原始裸指针 HttpMgr*
  • shared_ptr 是一个包装类，里面保存裸指针；shared_ptr ≠ 对象地址，类型不匹配，直接编译报错。
  • .get() 只是拿地址，不改变 shared_ptr 的 ref 计数。

说明：

  • 不是立刻马上 delete，而是：把这个 QNetworkReply 对象标记为待删除，等到当前 Qt 事件循环跑完之后，再自动 delete。

  • reply->finished这个 lambda 回调，本身还在 reply 对象触发的信号的调用栈里面。如果在信号回调内部直接delete reply，等于信号还没处理完，就把发送信号的对象销毁了，会造成野指针、程序崩溃。

  • deleteLater() 是 QObject 的成员函数，所有继承 QObject 的类都能用，QNetworkReply 继承 QObject。

  • 在 Qt 代码里写的 connect()，本质就是 QObject::connect()，二者是同一个函数，只是写法简写。

  • QObject 是 Qt 框架最基础的根类，几乎所有 Qt 核心类都继承它。
    例如：QDialog → QWidget → QObject
    QLabel → QWidget → QObject
    QNetworkAccessManager → QObject
    QNetworkReply → QObject
    HttpMgr : public QObject
    ClickedLabel : public QLabel(最终QObject)
