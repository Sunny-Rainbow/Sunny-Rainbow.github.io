03 · 验证码服务篇（VarifyServer/）

VarifyServer 是 Node.js gRPC 微服务：只负责「生成验证码 → 写 Redis → 发邮件」。
不直接对 Qt 开放，只被 GateServer 调用。

一、模块联系

1.1 关系总图

1.2 协作要点

关系 说明
Gate ↔ Varify 仅 gRPC，端口默认 50051
Varify ↔ Redis 验证码缓存；Gate 注册时也读同一 Key
Varify ↔ 邮箱 nodemailer 发信；失败走 Exception
与 MySQL 本服务当前发码路径不写 MySQL

二、各模块功能

文件 功能
server.js 入口；实现 GetVarifyCode；绑定 0.0.0.0:50051
proto.js 用 @grpc/proto-loader 加载 message.proto
message.proto VarifyService.GetVarifyCode 定义
redis.js ioredis：GetRedis / SetRedisExpire
email.js nodemailer 创建 transport 并 sendMail
config.js / config.json 邮箱、Redis 等配置
const.js code_ = "code_"；错误码 Success/RedisErr/Exception
package.json 依赖与 npm run serve

Redis Key 约定

GateServer 使用同一前缀宏：CODEPREFIX "code_"。

三、代码讲解

3.1 启动 gRPC 服务

说明：

  • addService：把 RPC 名映射到本地函数。
  • createInsecure()：教学环境无 TLS；生产应加证书。
  • 新版 @grpc/grpc-js 中 server.start() 可省略（会有 DeprecationWarning）。

3.2 GetVarifyCode 主流程

逐步理解：

  1. 先查 Redis：若已有未过期验证码 → 复用（避免刷接口一直换码）。
  2. 没有则生成 UUID，截成 4 位，SET + EXPIRE 600。
  3. Redis 写失败 → 返回 RedisErr，不发邮件。
  4. 发邮件；成功回 error: 0。
  5. 注意：proto 里有 code 字段，但当前实现不把验证码回给 Gate，只放 Redis + 邮件；Gate 注册时自己读 Redis。

3.3 Redis 封装

学习注意：

  • 若在 error 回调里调用 quit()，连接会永久关闭，后续全是 Connection is closed。
  • 本地 Redis 端口/密码必须与 config.json 一致（本项目常用 6380）。

3.4 发邮件

说明：

  • 163 等邮箱需开启 SMTP 并使用授权码。
  • 发件失败会 throw → 被 GetVarifyCode 的 catch 转成 Exception。

3.5 Proto 契约

Gate 侧 C++ 与 Node 侧必须用同一套 proto（或兼容字段编号），否则会联调失败。

四、验证码服务自测清单

  1. npm run serve 后是否打印 grpc server started？
  2. Redis 是否在线？启动时有无 RedisCli connect error？
  3. Gate 调一次后，本服务是否打印 email is ...？
  4. Redis 中是否出现 code_<邮箱>？
  5. 邮箱是否收到 4 位验证码？
