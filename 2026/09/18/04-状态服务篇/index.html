04 · 状态服务篇（StatusServer/）

StatusServer 负责：登录成功后，给用户分配一台 ChatServer，并签发 Token。
GateServer 在 /user_login 验密通过后，通过 gRPC 调用它。

一、模块联系

1.1 关系总图

1.2 协作要点

关系 说明
Gate → Status 仅登录成功后调 GetChatServer
Status → Redis 写入 utoken_<uid>，供 ChatServer / Login RPC 校验
Status ↔ ChatServer 列表 来自 config.ini 的 [chatservers]
负载均衡 按 Redis logincount 选最少连接的逻辑已写但被注释，当前固定返回第一台

二、各模块功能

文件 功能
StatusServer.cpp 启动 gRPC、注册服务、信号处理退出
StatusServiceImpl.* 实现 GetChatServer / Login；选服、发 token
message.proto StatusService 定义
ConfigMgr.* 读 config.ini
RedisMgr.* Redis 连接池；存 token
DistLock.* Redis 分布式锁（扩展用）
ChatGrpcClient.* 向 ChatServer 发通知类 RPC（非登录主路径）
const.h USERTOKENPREFIX="utoken_"、错误码等
config.ini 监听地址、Redis、多台 chatserver

三、代码讲解

3.1 服务启动

说明：

  • Host 常用 0.0.0.0 表示监听所有网卡；Gate 侧配置连 127.0.0.1:50052。
  • Insecure 同样仅适合学习环境。

3.2 构造：加载聊天服列表

说明：

  • 名字列表用逗号分隔，再逐个 section 读 Host/Port。
  • 结果放进 _servers map，供分配使用。

3.3 GetChatServer：分配 + 发 Token

说明：

  1. 选一台 ChatServer；
  2. 生成 UUID token；
  3. Redis 记下 utoken_<uid>；
  4. 把 host/port/token 回给 Gate → 客户端。

3.4 如何选服（当前 vs 设计）

说明：

  • 学习时要分清「代码意图」和「当前生效行为」。
  • 要启用负载均衡，需 ChatServer 上报连接数到 Redis，并取消注释比较逻辑。

3.5 Login RPC（校验 token）

学习提示：

  • 这段 if (success) 的分支语义看起来与「找到 key 应成功」相反，更像是笔误或未完成逻辑。
  • 阅读时建议对照 ChatServer 实际登录校验方式，以「谁读 utoken_」为准。
  • Gate 登录主路径目前主要用的是 GetChatServer，不一定走到这个 Login RPC。

3.6 Proto 契约

与 GateServer 的 StatusGrpcClient、生成的 message.grpc.pb.* 对应。

四、状态服务自测清单

  1. StatusServer 启动是否监听 50052？
  2. config.ini 里 chatserver 列表是否非空？
  3. Gate 登录成功日志是否出现 succeed to load userinfo uid is ...？
  4. Redis 是否出现 utoken_<uid>？
  5. 客户端回包是否包含 host / token / uid？
