02 · 网关篇（GateServer/）

GateServer 是整个系统的 HTTP 门面：客户端只认识它；它再去调 VarifyServer、StatusServer、Redis、MySQL。

一、模块联系

1.1 关系总图

main (GateServer.cpp)
  ├─ ConfigMgr          读 config.ini
  ├─ io_context(主)     只负责 accept + 信号
  └─ CServer::Start()
        │
        ├─ AsioIOServicePool::GetIOService()   给连接挑一个工作线程的 io_context
        └─ async_accept → HttpConnection
              │
              ├─ http::async_read
              ├─ HandleReq()
              │     └─ LogicSystem::HandlePost / HandleGet
              │           ├─ VerifyGrpcClient  → VarifyServer :50051
              │           ├─ StatusGrpcClient  → StatusServer :50052
              │           ├─ RedisMgr          → Redis
              │           └─ MysqlMgr→MysqlDao → MySQL
              └─ WriteResponse() 短连接关闭

1.2 协作要点

模块 在链路中的位置
CServer 监听端口，接新连接
AsioIOServicePool 多 io_context 线程池，提高并发
HttpConnection 读 HTTP、调逻辑、写响应、超时
LogicSystem URL → 业务 handler 的注册表（核心编排）
VarifyGrpcClient 拿验证码 / 触发发邮件
StatusGrpcClient 登录后问「连哪台 ChatServer」
RedisMgr 读 code_<email> 校验验证码
MysqlMgr/Dao 注册、验密、改密

二、各模块功能

文件 功能
GateServer.cpp 入口：读端口、信号退出、CServer + ioc.run()
CServer.* async_accept，把 socket 交给 HttpConnection
HttpConnection.* Beast HTTP 读写、GET 参数解析、60s deadline
LogicSystem.* 注册 /get_varifycode 等路由并实现业务
AsioIOServicePool.* IO 线程池（round-robin）
ConfigMgr.* INI 配置单例
VarifyGrpcClient.* gRPC Stub 连接池 → GetVarifyCode
StatusGrpcClient.* gRPC Stub 连接池 → GetChatServer
RedisMgr.* hiredis 连接池封装
MysqlMgr.* / MysqlDao.* MySQL 业务与连接池
message.proto 与 Varify / Status 共用的 protobuf
const.h 错误码、CODEPREFIX="code_"、Defer
config.ini 各服务地址与 DB/Redis

HTTP 路由一览

方法 路径 作用
GET /get_test 调试：打印 query
POST /get_varifycode 调 VarifyServer 发验证码
POST /user_register Redis 校验码 + MySQL 注册
POST /reset_pwd Redis 校验码 + 更新密码
POST /user_login 按邮箱验密 + StatusServer 分配聊天服

三、代码讲解

3.1 入口：监听与退出

// GateServer.cpp
auto & gCfgMgr = ConfigMgr::GetInstance();
unsigned short gate_port = atoi(gCfgMgr["GateServer"]["Port"].c_str());

net::io_context ioc{ 1 };
net::signal_set signals(ioc, SIGINT, SIGTERM);
signals.async_wait([&ioc](auto& error, int) {
    if (!error) ioc.stop();
});

std::make_shared<CServer>(ioc, gate_port)->Start();
ioc.run();

说明：

  • 主 io_context 只跑 accept + 信号处理。
  • 真正处理 HTTP 的读写在 AsioIOServicePool 的工作线程上。

3.2 接受连接：接到线程池

void CServer::Start()
{
    auto self = shared_from_this();
    auto& io_context = AsioIOServicePool::GetInstance()->GetIOService();
    auto new_con = std::make_shared<HttpConnection>(io_context);

    _acceptor.async_accept(new_con->GetSocket(), [self, new_con](beast::error_code ec) {
        if (ec) { self->Start(); return; }
        new_con->Start();
        self->Start();   // 继续等下一个连接
    });
}

说明：

  • 每个连接绑定到池里的某个 io_context，避免单线程瓶颈。
  • Start() 递归挂新的 async_accept，形成持续监听。

3.3 HTTP 读 → 分发 → 写

void HttpConnection::Start()
{
    auto self = shared_from_this();
    http::async_read(_socket, _buffer, _request,
        [self](beast::error_code ec, std::size_t) {
            if (ec) return;
            self->HandleReq();
            self->CheckDeadline();
        });
}

void HttpConnection::HandleReq() {
    _response.version(_request.version());
    _response.keep_alive(false);   // 短连接

    if (_request.method() == http::verb::post) {
        bool ok = LogicSystem::GetInstance()->HandlePost(
            _request.target(), shared_from_this());
        if (!ok) {
            _response.result(http::status::not_found);
            // ...
        } else {
            _response.result(http::status::ok);
        }
        WriteResponse();
    }
}

说明：

  • 业务不在这里写，只负责协议层；具体逻辑全在 LogicSystem。
  • keep_alive(false)：一请求一响应后关连接，实现简单。

3.4 获取验证码路由

RegPost("/get_varifycode", [](std::shared_ptr<HttpConnection> connection) {
    auto body_str = boost::beast::buffers_to_string(connection->_request.body().data());
    Json::Value src_root;
    Json::Reader reader;
    if (!reader.parse(body_str, src_root) || !src_root.isMember("email")) {
        // 返回 Error_Json
        return true;
    }
    auto email = src_root["email"].asString();
    GetVarifyRsp rsp = VerifyGrpcClient::GetInstance()->GetVarifyCode(email);

    Json::Value root;
    root["error"] = rsp.error();
    root["email"] = src_root["email"];
    beast::ostream(connection->_response.body()) << root.toStyledString();
    return true;
});

说明：

  • Gate 自己不发邮件，只做 HTTP → gRPC 转发。
  • 验证码真正写入 Redis 在 VarifyServer 侧完成。

3.5 注册：校验码 + 写库

核心步骤（逻辑顺序）：

1. 解析 JSON：user / email / passwd / confirm / varifycode
2. passwd == confirm ?
3. Redis GET code_<email>，比对 varifycode
4. MysqlMgr::RegUser(name, email, pwd)  → CALL reg_user
5. 返回 uid 或 UserExist

对应代码要点：

std::string varify_code;
bool b_get_varify = RedisMgr::GetInstance()->Get(
    CODEPREFIX + email, varify_code);   // CODEPREFIX = "code_"

if (!b_get_varify) { /* VarifyExpired */ }
if (varify_code != src_root["varifycode"].asString()) { /* VarifyCodeErr */ }

int uid = MysqlMgr::GetInstance()->RegUser(name, email, pwd);

说明：

  • 客户端传来的 passwd 已经是 xorString 后的值，直接入库。
  • Redis Key 必须与 VarifyServer 一致：code_ + 邮箱。

3.6 登录：按邮箱验密 + 分配聊天服

auto email = src_root["email"].asString();
auto pwd = src_root["passwd"].asString();

UserInfo userInfo;
bool pwd_valid = MysqlMgr::GetInstance()->CheckPwd(email, pwd, userInfo);
if (!pwd_valid) {
    root["error"] = ErrorCodes::PasswdInvalid;
    // ...
}

auto reply = StatusGrpcClient::GetInstance()->GetChatServer(userInfo.uid);
root["error"] = 0;
root["email"] = email;
root["user"] = userInfo.name;
root["uid"] = userInfo.uid;
root["token"] = reply.token();
root["host"] = reply.host();

MySQL 侧：

// MysqlDao::CheckPwd
const char* sql = "SELECT uid,name,pwd,email FROM user WHERE email = ?";
// ... 取出 origin_pwd 后
if (pwd != origin_pwd) return false;

说明：

  • 登录键是 email（与 Qt 登录页一致），不是用户名。
  • 验密通过后才问 StatusServer 要 host/token。

3.7 gRPC 客户端（验证码）示意

GetVarifyRsp VerifyGrpcClient::GetVarifyCode(std::string email) {
    ClientContext context;
    GetVarifyRsp reply;
    GetVarifyReq request;
    request.set_email(email);

    auto stub = pool_->getConnection();
    Status status = stub->GetVarifyCode(&context, request, &reply);
    pool_->returnConnection(std::move(stub));

    if (!status.ok())
        reply.set_error(ErrorCodes::RPCFailed);
    return reply;
}

说明：

  • Stub 池避免每次新建 Channel。
  • 配置里 Host/Port 大小写必须与 config.ini 键名一致（例如 Host vs host）。

四、网关自测清单

  1. config.ini 中 Varify / Status / Redis / MySQL 是否都能连通？
  2. 收到 /get_varifycode 后 VarifyServer 是否有日志？
  3. 注册时 Redis 是否存在 code_<email>？
  4. 登录 JSON 是否含 email（不是只发 user）？
  5. 登录成功后是否拿到 token 与 host？
