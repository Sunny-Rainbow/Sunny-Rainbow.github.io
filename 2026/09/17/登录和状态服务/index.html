1. 项目全景

本项目是一个分布式即时通讯（IM）前置系统：客户端先通过 HTTP 完成注册/登录，再准备连接聊天服务器进行长连接通信。

当前仓库主要模块：

目录 角色 语言 / 框架
chat/ Qt 桌面客户端 C++ / Qt 6
GateServer/ HTTP 网关（对外入口） C++ / Boost.Asio + Beast
VarifyServer/ 邮箱验证码服务 Node.js / gRPC
StatusServer/ 状态与聊天服分配服务 C++ / gRPC
MySQL 持久化用户数据 关系型数据库
Redis 验证码等短期缓存 内存 KV

说明：StatusServer 的配置里已经预留了 chatserver1/2（聊天业务服）。客户端登录成功后会拿到 host/token，用于后续 TCP 长连接；ChatServer 本体可能在后续课程/其他仓库中完善。

2. 整体架构图

记忆口诀：

  • 客户端只认识 GateServer（HTTP）
  • GateServer 对外当门面，对内调 gRPC / Redis / MySQL
  • VarifyServer 只管验证码邮件 + 把验证码写 Redis
  • StatusServer 只管“这个用户该连哪台聊天服”

3. 各模块职责与技术栈

3.1 Qt 客户端 chat/

职责： 用户界面与请求发起（登录、注册、重置密码）。

主要技术：

技术 用途
Qt Widgets 窗口、输入框、按钮、QStackedWidget 翻页
Qt Network (QNetworkAccessManager) 发 HTTP POST
QJsonObject / QJsonDocument 组装/解析 JSON
QTimer 验证码按钮倒计时、注册成功倒计时
信号槽 HttpMgr 回包分发给登录/注册模块
xorString 密码异或“简单加密”后再上传

关键文件：

  • httpmgr.cpp：统一发 HTTP，按 Modules 转发回包
  • logindialog.cpp：登录，请求 /user_login
  • registerdialog.cpp：注册，请求 /get_varifycode、/user_register
  • resetdialog.cpp：重置密码，请求 /reset_pwd
  • global.cpp：gate_url_prefix、xorString
  • config.ini：GateServer 地址（如 localhost:8080）

3.2 GateServer（HTTP 网关）

职责： 对外提供 REST 风格 HTTP 接口；对内编排验证码、注册、登录、重置密码。

主要技术：

技术 用途
Boost.Asio 异步 IO、线程池 AsioIOServicePool
Boost.Beast HTTP 解析与响应
JsonCpp 解析请求体 / 构造响应
gRPC C++ 调用 VarifyServer、StatusServer
Protobuf RPC 消息定义（message.proto）
libmysql / 连接池 读写用户表
hiredis / Redis 连接池 读验证码 code_<email>
单例 (Singleton) LogicSystem、RedisMgr、MysqlMgr 等

对外 HTTP 接口（见 LogicSystem.cpp）：

路径 方法 作用
/get_varifycode POST 向 VarifyServer 要验证码并发邮件
/user_register POST 校验验证码后写入 MySQL
/reset_pwd POST 校验验证码后更新密码
/user_login POST 按邮箱验密，再向 StatusServer 要聊天服

3.3 VarifyServer（验证码服务）

职责： 收到 gRPC 请求后生成验证码、写入 Redis、发邮件。

主要技术：

技术 用途
Node.js 服务运行时
@grpc/grpc-js + @grpc/proto-loader gRPC 服务端
uuid 生成验证码（截取前 4 位）
ioredis 读写 Redis
nodemailer SMTP 发邮件

关键文件：

  • server.js：实现 GetVarifyCode
  • email.js：发信
  • redis.js：GetRedis / SetRedisExpire
  • config.json：邮箱账号、Redis 地址

Redis Key 约定：

GateServer 注册/重置时用同一前缀 CODEPREFIX = "code_" 去读，所以两边必须连同一套 Redis。

3.4 StatusServer（状态 / 分配服务）

职责： 登录成功后，为用户分配一台 ChatServer，并生成 token。

主要技术：

技术 用途
gRPC C++ 提供 StatusService.GetChatServer
Protobuf 请求 uid，返回 host/port/token
Boost.UUID 生成 token
Redis 可记录登录人数、token（扩展负载均衡）
ConfigMgr 读取多台 chatserver 配置

接口语义：

GateServer 登录成功后调用它，再把结果返回给 Qt 客户端。

3.5 MySQL

职责： 持久化用户账号。

典型字段（以 user 表 / reg_user 存储过程为准）：

  • uid
  • name（用户名）
  • email
  • pwd（客户端 xorString 后的密码）

GateServer 通过：

  • RegUser → CALL reg_user(...)
  • CheckPwd → SELECT ... FROM user WHERE email = ? 再比对密码
  • UpdatePwd → 更新密码

3.6 Redis

职责： 缓存短期数据，尤其是验证码。

本项目中最关键的用途：

  1. VarifyServer 写入 code_邮箱
  2. GateServer 注册/重置时读取并比对

其他用途（StatusServer）：登录计数、token 缓存等（代码中有相关设计）。

6. 启动顺序建议

本地联调时建议按依赖从下往上启动：

  1. Redis（127.0.0.1:6380，密码与配置一致）
  2. MySQL（能连上，且存在 user 表、reg_user 存储过程）
  3. VarifyServer：npm run serve（监听 50051）
  4. StatusServer（监听 50052）
  5. GateServer（监听 8080）
  6. Qt 客户端

缺一不可的常见现象：

现象 常见原因
参数错误 / RPCFailed Gate 连不上 Varify/Status，或配置 Host/Port 写错大小写
Redis Connection is closed Redis 没起，或 Varify 错误后 quit 了连接
user or email exist 邮箱/用户名已注册
user pwd not match 曾按用户名查库、或密码未 xor、或邮箱不存在

7. 推荐源码阅读顺序

按“从外到内”读，更容易建立全局图：

  1. chat/main.cpp → 读 config.ini，得到 gate_url_prefix
  2. chat/httpmgr.cpp → HTTP 怎么发、信号怎么分模块
  3. chat/registerdialog.cpp / logindialog.cpp → 业务请求字段
  4. GateServer/CServer.cpp + HttpConnection.cpp → 连接怎么接、HTTP 怎么读
  5. GateServer/LogicSystem.cpp → 最重要的业务编排
  6. GateServer/VarifyGrpcClient.* / StatusGrpcClient.* → 如何调 gRPC
  7. VarifyServer/server.js → 验证码与邮件
  8. StatusServer/StatusServiceImpl.cpp → 如何选 ChatServer、发 token
  9. GateServer/MysqlDao.cpp / RedisMgr.cpp → 持久化与缓存细节

8. 设计思想小结（面试/自测可用）

  1. 网关模式：客户端只打一个 HTTP 入口，降低耦合。
  2. 服务拆分：验证码、状态分配、业务网关职责分离，可独立扩容。
  3. 同步短请求用 HTTP；内部高性能调用用 gRPC。
  4. 热点短数据放 Redis，长期数据放 MySQL。
  5. 连接池：MySQL / Redis / gRPC Stub 池，提升并发。
  6. IO 线程池：AsioIOServicePool 提高 GateServer 并发处理能力。

学完后可用下面问题自测：

  1. 为什么客户端不直接连 VarifyServer？

  3. 注册时 GateServer 如何确认“这是刚才发到邮箱的码”？
  4. 登录成功后为什么还要找 StatusServer？
  5. xorString 是加密还是混淆？生产环境应如何改进？
